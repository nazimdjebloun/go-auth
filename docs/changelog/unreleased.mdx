# Unreleased

## Added

- Opt-in app authorization through `WithAppPermissions`, with one role per
  account, protected `admin` and `user` identities, custom roles, and explicit
  granular grants independent of organization membership.
- Optional role, business permission, assignment and self-access HTTP routes;
  direct backend checks through `Services.AppPermissions` and
  `Auth.RequireAppPermission` middleware.
- A fixed library permission catalog and protected-admin-only atomic bulk
  installation/removal. Local CLI commands can install selected keys, install
  all keys explicitly, or apply a mixed create/delete batch.
- Optimistic revisions, delegation limits, current SQL checks, audit events,
  and default administrative MFA for current library-grant holders.

## Changed

- With app permissions enabled, existing administrative operations check exact
  action keys. Missing library definitions leave actions protected-admin-only;
  the retained legacy account role never supplies enabled-mode access.
- Signup, invitation redemption and OAuth account creation assign the configured
  default role within the account transaction. Reinstalling a removed library
  permission does not restore its deleted grants.
- The canonical schemas now include app authorization tables and account role
  columns, including for installations that leave the feature disabled. This
  change provides fresh-install schemas without automatic migration or backfill.

See the [app permission guide](../guides/app-permissions.mdx) and
[route reference](../routes/authorization.mdx) for setup and request details.
